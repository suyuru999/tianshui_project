# 天水流域生态环境监管系统现有功能说明

## 一、系统定位

天水流域生态环境监管系统面向流域生态环境管理、遥感数据分析、生态修复工程监管和公众反馈收集等场景，提供“地图展示、数据上传、生态分析、气候监测、工程叠加分析、业务图层管理”一体化能力。

系统以地图为主要工作界面，结合遥感影像、矢量图层、气候数据和生态工程数据，帮助管理人员查看流域空间信息、管理业务图层、分析生态环境变化，并形成可追溯的数据记录和处理结果。

## 二、系统总体能力

### 1. 地图综合展示

系统提供基于 Web 的地图展示界面，支持流域范围、乡镇边界、水系点位、业务图层等空间数据加载和展示。

现有能力包括：

- 在线地图浏览、缩放、平移、复位等基础操作
- 流域相关矢量数据展示
- 图层显隐控制和图层管理
- 支持业务图层叠加展示
- 支持 WMS、WFS、WCS 等标准地理服务接入
- 支持 Shapefile、KML、GeoTIFF 等常见地理空间数据格式

该模块主要用于作为系统的空间数据入口，帮助用户在地图上直观查看各类生态环境数据。

### 2. 用户与后台管理

系统内置用户管理和后台管理能力，支持管理员对系统基础数据、用户数据、业务记录和处理结果进行维护。

现有能力包括：

- 管理员后台登录
- 用户信息管理
- 用户角色区分，包括管理员、普通用户、专家等
- 后台查看和管理上传记录、分析任务、反馈数据等
- 支持后续扩展更细粒度的模块权限

该模块用于保障系统运行过程中的数据管理和权限控制。

### 3. 业务图层管理

系统支持将用户上传的空间数据作为业务图层进行管理，并发布到 GeoServer 形成标准地图服务。

现有能力包括：

- 上传 Shapefile 压缩包
- 上传 KML 文件
- 上传 GeoTIFF 栅格文件
- 接入外部 WMS、WFS、WCS 服务
- 自动识别图层类型，包括矢量图层和栅格图层
- 自动生成图层服务地址
- 自动发布到 GeoServer
- 自动生成并应用基础样式
- 记录图层发布状态、错误信息和操作日志

业务图层发布成功后，可形成 WMS/WFS/WCS 服务地址，用于前端地图加载、外部系统调用或后续空间叠加分析。

### 4. 遥感影像管理与生态指数分析

系统支持遥感影像数据上传、记录管理和生态指数计算，为流域生态环境评价提供数据基础。

现有能力包括：

- 上传遥感影像文件
- 记录影像名称、类型、采集日期、中心经纬度等信息
- 支持 Landsat、Sentinel、自定义影像等类型记录
- 支持 NDVI、NDWI、NDBI、NDSI 等常见遥感生态指数
- 支持绿度、湿度、干度、热度等生态环境指标
- 支持 RSEI 遥感生态指数综合评价
- 记录计算任务状态、进度、错误信息和完成时间
- 保存指数结果文件、可视化图片和统计结果

该模块可用于生态质量评估、植被覆盖分析、水体变化分析、建设用地影响分析等业务场景。

### 5. 气候监测数据分析

系统支持气候数据文件上传与统计分析，可对流域气候相关指标进行汇总和可视化。

现有能力包括：

- 上传 CSV、Excel、GeoTIFF、ADF ZIP 等气候数据文件
- 记录气候文件状态，包括已上传、处理中、完成、失败
- 支持温度、降水量、湿度、风速等指标统计
- 生成平均值、最大值、最小值、标准差等分析结果
- 保存图表数据和分析结果记录
- 支持通过任务状态追踪分析过程

该模块可用于气候背景分析、生态环境变化辅助判断和监测数据归档。

### 6. 生态修复工程与叠加分析

系统支持生态指数数据和生态修复工程数据上传，并进行叠加分析，用于评估工程影响范围和风险等级。

现有能力包括：

- 上传生态指数 JSON 文件
- 上传生态修复工程 GeoJSON 数据
- 创建叠加分析任务
- 记录任务状态、进度、分析结果和风险等级
- 生成风险等级栅格文件和影响强度栅格文件
- 保存分析结果数据和空间展示元数据

该模块用于支撑生态修复工程监管，帮助判断工程与生态敏感区域、生态风险区域之间的空间关系。

### 7. 民众意见反馈

系统提供公众反馈数据收集能力，可用于接收生态环境相关意见、问题和建议。

现有能力包括：

- 提交功能建议、问题报告、数据纠错和其他反馈
- 记录反馈标题、内容、联系方式和提交时间
- 后台查看和管理反馈记录
- 支持后续扩展处理状态、责任部门和闭环跟踪流程

该模块可作为公众参与和社会监督入口。

## 三、系统技术组成

### 1. 前端展示层

前端采用 Vue 技术构建，主要负责页面展示、地图交互、文件上传、数据列表和分析结果展示。

主要页面包括：

- 地图首页
- 遥感分析页面
- 生态指数页面
- 气候监测页面
- 叠加分析页面
- 民众反馈页面

### 2. 后端服务层

后端采用 Django 和 Django REST Framework 构建，主要负责接口服务、业务逻辑、文件接收、任务管理和数据库读写。

后端提供统一 API 接口，供前端页面调用。

### 3. 数据库层

系统当前使用 PostgreSQL 作为主数据库。

PostgreSQL 主要保存：

- 用户信息
- 上传文件记录
- 业务图层记录
- 遥感影像记录
- 生态指数结果
- 气候分析结果
- 处理任务状态
- 民众反馈记录
- 操作日志和元数据

大文件本身不直接存入数据库，而是存放在服务器媒体目录中，数据库保存文件路径和相关业务信息。

### 4. 地图服务层

系统使用 GeoServer 提供空间数据服务发布能力。

GeoServer 主要负责：

- 发布 Shapefile、GeoTIFF 等空间数据
- 生成 WMS、WFS、WCS 标准服务
- 提供地图图层给前端加载
- 管理图层样式和工作空间

### 5. 任务处理层

系统支持 Celery 任务机制，用于处理耗时的数据分析任务。

本地开发环境中，任务可同步执行，便于演示和测试；生产环境可接入 Redis 等消息队列，实现异步任务处理。

## 四、典型业务流程

### 1. 业务图层上传与展示流程

用户上传 Shapefile、KML 或 GeoTIFF 文件。

系统保存文件并创建业务图层记录。

后端调用 GeoServer 发布图层。

GeoServer 生成 WMS/WFS/WCS 服务地址。

前端地图加载图层并展示。

后台记录发布状态、服务地址和操作日志。

### 2. 遥感生态指数分析流程

用户上传遥感影像。

系统保存影像文件和基础信息。

用户选择需要计算的生态指数。

后端创建处理任务并执行计算。

系统保存指数结果文件、可视化图片和统计指标。

前端展示计算结果和任务状态。

### 3. 气候数据分析流程

用户上传气候监测数据文件。

系统保存文件并创建数据记录。

用户发起气候分析。

后端计算温度、降水、湿度、风速等统计指标。

系统保存分析结果和图表数据。

前端展示分析结果。

### 4. 生态工程叠加分析流程

用户上传生态指数文件和生态修复工程文件。

系统创建叠加分析任务。

后端进行空间叠加和风险判断。

系统生成风险等级、影响强度和空间结果文件。

前端地图展示分析成果。

当前系统已完成 PostgreSQL 数据库接入，并完成主要链路冒烟验证。

已验证通过的能力包括：

- PostgreSQL 数据库连接正常
- 管理员后台可用
- 民众反馈可提交并入库
- 遥感影像可上传并生成记录
- 气候数据可上传并完成分析
- 业务图层可上传、发布到 GeoServer，并成功应用样式
- GeoServer 工作空间和地图服务状态正常
- 系统健康检查通过
- 前端项目可正常构建

## 六、系统价值

该系统可为流域生态环境管理提供统一的数据入口、地图展示平台和分析工具。

主要价值包括：

- 将分散的遥感、气候、工程、反馈等数据统一管理
- 通过地图直观展示流域生态环境相关信息
- 支撑生态指数分析和生态质量评估
- 支撑生态修复工程影响分析和风险判断
- 支持业务图层标准化发布和复用
- 为后续监测、预警、评估和汇报提供数据基础
